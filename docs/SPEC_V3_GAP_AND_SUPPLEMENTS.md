## 3. 현재 구현 중 보완이 필요한 점

### 3.1 화면·UI

| 항목 | 현상 | 보완 제안 |
|------|------|-----------|
| **갤러리 empty** | 태그 필터 시 결과 없음 — "선택한 태그에 맞는 템플릿이 없습니다" | v3와 동일한 톤 유지. 추가로 "태그 해제" 유도 문구 가능 |
| **업로드 가이드** | "어떤 내용을 넣으면 좋을까요?" 아코디언 — 표·가이드 있음 | v3 "지원/미지원 파일 형식" 안내는 현재 표에 반영됨. 유지 |
| **미리보기 기본 뷰** | 모바일(375px) 기본 뷰로 설정됨 | v3 반응형 요구 충족. 유지 |
| **관리자 문의** | 문의 테이블 컬럼: 유형·제목·문의자·상태·일시·답변 | v3 "유형 \| 제목 \| 이메일 \| 날짜 \| 상태 \| 답변" — 이메일은 문의자와 동일. 현재 구조 적절 |

### 3.2 에러·예외 처리

| 항목 | v3 요구 | 현재 | 보완 제안 |
|------|----------|------|-----------|
| **E-네트워크 (SC-01)** | 템플릿 수 뱃지 로드 실패 → 숫자 숨김, 레이아웃 유지 | count 쿼리 실패 시 뱃지 미표시 | ✓ 이미 동일하게 동작 |
| **E-fetch (SC-03)** | 목록 로드 실패 → "다시 시도" 버튼 | React Query retry·에러 시 빈 목록 또는 에러 UI | 갤러리 fetch 실패 시 "다시 시도" 버튼 명시 권장 |
| **에러 바운더리** | "예상치 못한 오류" 문구 | "오류가 발생했습니다." | ErrorBoundary 문구만 스펙대로 수정 |

### 3.3 기능·데이터

| 항목 | 현재 | 보완 제안 |
|------|------|-----------|
| **inquiries.type** | 기본값 DB '기타', 폼 기본 '서비스 문의' | 기존 데이터 마이그레이션 시 type NULL → '기타' 처리 확인 |
| **주문 테이블** | users(email) JOIN·plan_type 표시 | ✓ 반영됨. 정렬·필터 추가 시 v3와 충돌 없음 |
| **Realtime (F-015)** | 2초 폴링으로 status 감지 | v3 "Realtime 미적용 — 선택 사항". 현재 방식 유지 가능 |

## 5. 우선순위별 보완 제안

### 단기 (UX·스펙 정합)
